Notifications Strategy

Pillar 8 · May 6, 2026 · Strategy Locked
0 comments

1. Overview

Pillar: 8 (Notifications & Nudges)
Purpose: Drive user return and deeper dwelling engagement through sparse, contextual invitations to dwell
Scope: Push notifications + in-app notifications (MVP); no email
Status: Strategy locked, ready for implementation
Philosophy: "Invitations to dwell," not "reminders to use the app"

2. Product Purpose

The Problem Notifications Solve

  • Phase 1 validation: 100% capture adoption, 0% return rate
  • Root cause: Users aren't returning to reflect on moments they captured
  • Solution: Sparse, meaningful notifications that invite users back to dwell on their moments

Why Pillar 8 (Last)

  • Notifications only work after there are compelling experiences (Prayer/Dwelling from Pillar 3)
  • Without good prayer prompts, notifications just nag users to use an empty app
  • Pillar 5 (Search) makes moments accessible; Pillar 8 invites users back to them

3. Success Criteria

Qualitative

  • Notifications feel like invitations, not reminders
  • Users perceive notifications as genuinely helpful, not pushy
  • Notifications respect the spiritual/faith tone of Dwellable (not productivity-gamified)

Quantitative

  • D7 Retention increases to >35% (from 0% baseline)
  • Formation Engagement Rate (% of users dwelling) increases >20% (MVP: dwelling = prayer on a captured moment OR journal return — prompt response not counted)
  • Click-through rate on notifications >40% (users act on invitations)
  • Opt-out rate <10% (users keep notifications enabled)
  • No increase in churn from notification fatigue

5. Funnel Stages — Notification Playbook

We segment by where someone is in the funnel — not by who we think they are. Archetypes are Post-MVP.

Funnel: Onboarded → Captures → Responds to Prompt → Prays → Returns to Journal → Consistent Dwelling

Dwelling (MVP) = praying on a captured moment OR returning to a journal entry (to edit, add context, or pray/journal from a notification). Responding to a prompt is not counted as dwelling — it's a positive signal that reduces notification urgency but does not advance funnel stage. A user's funnel stage is determined by the deepest dwelling act they've taken.

Each stage below specifies: Condition (who this applies to), Why (intervention goal), When to fire (timing trigger), and Cool-off (suppression rules) — followed by Push and In-App message options.

Stage A0 — Onboarded, incomplete setup — MVP

Phase: MVP

Condition: Account partially created — started onboarding but did not complete (intent, support style, or theological framework not captured)

Why: Recover the install. They showed intent (downloaded, started) but didn't finish. Goal is not to pressure completion — it's to remind them why they came and make re-entry frictionless.

When to fire: Day 2 after install if onboarding is incomplete (push, 1x). On re-open (in-app, pick up where they left off).

Cool-off: 1 push max. After Day 7 with no completion, stop all outbound — await organic return.

Push

  • "You started something. Finish setting up so we can meet you where you are."
  • "Your Dwellable profile is almost ready — a few steps to make it yours."

In-App

Placement: First screen on first open — before onboarding asks anything. Then resumes onboarding. Dismiss: onboarding completed.

  • "You're here. That took something. This space is yours."
  • "Welcome back. Let's finish getting you set up." (re-open)

Stage A — Onboarded, no captures yet — MVP

Phase: MVP

Condition: Onboarding complete, 0 moments captured

Why: Drive the first capture — the first meaningful investment. Until someone captures, nothing else in the product has context to work with.

When to fire: Day 3 with no capture (push, 1x). Create tab empty state surfaces Day 1 (in-app).

Cool-off: 1 push total before first capture. Suppress all push after first capture is made. AI personalization of the first in-app prompt is MVP (not Post-MVP).

Push

  • "Ready to capture what's on your heart?"
  • "What's something you'd like to remember from this week?"
  • "Your voice is worth capturing."

In-App

Placement: Create tab empty state (Day 1). Dismiss: first capture made.

  • "Start by capturing a moment — a thought, a feeling, something that happened."

Stage B1 — Captured, no dwelling — MVP

Phase: MVP

Condition: Any capture that exits without prayer — fires after every unprayed capture, not just the first

Why: Prayer is invited after every capture. The emotional context is always live right after a moment is captured — that window should never close without an invitation.

When to fire: Same evening or next morning after any capture without prayer (push, within ~12 hours). Weekly cadence continues until prayer is recorded.

Cool-off: Push + in-app. If user responds to one, suppress the other. Weekly push at 8am (dweller's time zone) — at most 1 push/week regardless of capture volume (prolific capturers don't get multiple weekly pushes). After 4 no-clicks, expire. If they click but don't pray, continue weekly cadence.

Push

  • "You captured something earlier. When you're ready, would you like to pray on it?"
  • "How has your heart been this week? Anything to reflect on?"
  • "Your moments are waiting. Ready to go deeper?"

In-App

Placement: Immediately after capture, before exit. Today tab moment card on return. Dismiss: prayer started or prompt response submitted.

  • "Would you like to take a moment to pray on what you just shared?"
  • "You captured this — ready to pray on it?"

Stage B2 — Captured, responded to prompt, no prayer — MVP

Phase: MVP

Condition: ≥1 moment captured, ≥1 prompt response, 0 prayers recorded

Why: They're already dwelling — responding to a prompt IS a form of dwelling. Tone is softer, urgency is lower. We're not pulling them in; we're inviting the next step.

When to fire: Same evening or next morning after capture with no prayer (push, within ~12 hours). Weekly cadence continues until prayer is recorded. Today tab contextual on return (in-app).

Cool-off: Push + in-app. If user responds to one, suppress the other. Weekly push at 8am (dweller's time zone). After 4 no-clicks, expire. If they click but don't pray, continue weekly cadence. (Matches B1 cadence — B2 differs only in tone and message variants, not delivery rhythm.)

Push

  • "You captured something earlier. When you're ready, would you like to pray on it?"
  • "Your moments have depth. Ready to bring them to prayer?"
  • "You've been reflecting. How's your heart in prayer?"

In-App

Placement: Today tab, below recent moment. Dismiss: prayer started.

  • "You've reflected on this — want to pray on it too?"

Stage C1 — First prayer, no journal return (L5a) — MVP

Phase: MVP

Condition: ≥1 prayer recorded; has not returned to a journal entry; active within last 14 days

Why: They prayed but haven't seen what came from it. A journal entry was created after prayer — they may not know it's there, or haven't felt the pull to return. Goal: surface the connection between the moment they prayed and the artifact it generated.

When to fire: Immediately after prayer closes (in-app — show the journal card before they exit). Push: weekly cadence at 8am (dweller's time zone) starting 7 days after prayer with no journal return.

Cool-off: In-app: once per prayer session. Push: 1/week at 8am (dweller's time zone). Stop after 2 ignores per C1 notif.

Push

Three message variants — rotate or select contextually based on user data:

  • Brings dweller to journal: "You shared your heart earlier, and here's how we honored it..." (Surfaces the journal card; on first open, walks the user through journal features — edit, add context, reflect, pray.)
  • Brings dweller to capture: "How have you been feeling since prayer?"
  • Brings dweller to capture: "Where's your heart at regarding {subject}?" (Personalized variant — requires readable subject metadata; falls back to generic prompt if unavailable.)

In-App

Placement: Immediately after prayer closes, before exiting prayer flow. Shows journal card generated from that prayer. Dismiss: journal entry opened.

First-time experience: When the journal card surfaces for the first time, include a brief orientation — "here's what you can do with this." Show the available actions (edit, add context, reflect, pray). FTUE only; ongoing surfacing is the entry itself.

  • "Your moment was written down. Want to see it?"
  • "Here's what came from what you just brought to God." [surfaces journal card]

Stage C2 — Journal return, no prayer (L5b) — MVP

Phase: MVP

Condition: Has returned to ≥1 journal entry; 0 prayers ever recorded

Why: They found their way to the journal (likely through capturing and AI synthesis) but haven't discovered prayer. This is the journal-first path. Goal: invite prayer as the natural next step — not as something new, but as something that belongs alongside what they're already doing.

When to fire: After 2nd+ journal return with no prayer (in-app nudge below journal body). Push: 5–7 days after last journal activity with no prayer recorded.

Cool-off: 1 push max in first month. Stop outbound if no action in 3 weeks — await organic return. In-app: shows once per journal entry session, no stacking. (Sparser than B1/B2 — they've already found a dwelling path; prayer is the next step, not an urgent one.)

Push

  • "You've been reflecting. Ready to bring it to prayer?"
  • "Your journal has depth. Prayer is the next step, when you're ready."

In-App

Placement: After reading a journal entry — below the journal body. Dismiss: prayer initiated.

  • "Want to pray on what you just read?"
  • "This moment has been captured and reflected on. Prayer is the next step."

Stage C3 — Prayed and returned to journal, now quiet — MVP

Phase: MVP

Condition: ≥1 prayer AND ≥1 journal return recorded; no dwelling of any kind in 14+ days

Why: They've completed the full loop. They know what dwelling looks like. Re-invite gently — not with instruction or explanation, just with presence. The tone is familiar, not pedagogical.

When to fire: 14+ days since last dwelling act (push). Today tab on return (in-app, oldest unprayed moment surfaced).

Cool-off: 1x/month. Reduce to 1x/6 weeks after 3 no-clicks.

Push

  • "It's been a little while. How's your heart?"
  • "You have moments worth returning to. Ready to dwell?"
  • "Whenever you're ready, your moments are here."

In-App

Placement: Today tab, top of feed — oldest unprayed moment surfaced. Dismiss: any dwelling act.

  • "Whenever you're ready."

Stage D — Actively dwelling — MVP: silence • Post-MVP: FI-triggered

Phase: MVP — silence (0 push). Post-MVP — Formation Intelligence-triggered push, 0–1 per quarter max.

Condition: Prayer, prompt response, or journal return within the past 7–10 days

Why: Don't interrupt what's working. The product experience is the nudge. Stay mostly silent — presence over prompting.

When to fire: MVP: no push. Post-MVP: rare high-signal Formation Intelligence event only. In-app: contextual prompts within prayer flow only.

Cool-off: MVP: 0 push. Post-MVP: 0–1 per quarter maximum.

Push

MVP: none. Post-MVP only:

  • "Something keeps showing up in your moments — want to explore it?"

In-App

Placement: Contextual prompts within prayer flow only. Post-MVP: Formation Intelligence insights surfaced on Today tab.

Dormancy Reset Rule

Any user who reaches Stage D (actively dwelling) and then goes quiet for 14+ consecutive days is automatically routed to Stage C3 notification logic. No penalty framing — the same gentle re-invite applies regardless of how active they were before.

The transition is invisible to the user. Functionally: Stage D check runs daily; if last dwelling act is 14+ days ago, switch to C3 rules. Escalation follows normal C3 cool-off from that point.

Global Frequency Caps

  • Push: Max 1–2 per user per month across all stages — exception: B1/B2 operate on weekly cadence (prayer is time-sensitive; caps don't override active discovery stages)
  • In-App: 1 active nudge visible at a time; no stacking; dismiss on action

Optimal Push Send Time

  • Primary: User's typical app-open time (inferred from usage data)
  • Fallback: 9am local time if usage pattern is unclear
  • Blackout: Never between 10pm–7am local time

Note: Archetype labels are deferred to Post-MVP. The data from stages A0–D will surface the real patterns. We name them then, not now.

6. Personalization Rules (Metadata-Based, Due to E2E Encryption)

NOTE: Due to Pillar 2 (E2E Encryption), user moments are encrypted client-side. We cannot read plaintext. Therefore, notifications are personalized using metadata only, not moment content.

What we CAN personalize (metadata)

  • ✓ Timing (when user typically opens app)
  • ✓ Dwelling history (prayer vs. prompt preference)
  • ✓ Funnel stage (A–D)
  • ✓ Engagement frequency (# of moments captured, # of prayers, # of prompt responses)

What we CANNOT personalize (encrypted)

  • ✗ Moment themes ("You captured about faith")
  • ✗ Specific moment content (reference to what user wrote)

Generic Fallbacks (Always Available)

  • "How has your heart been this week? Anything to reflect on?"
  • "You have unresponded moments. Ready to dwell?"
  • "Your moments are waiting."

8. Privacy & E2E Encryption Implications

Privacy Promise (unchanged):

"Your responses are end-to-end encrypted. We never see your moments."

Notification Transparency

  • Notifications are generated using metadata (timing, engagement patterns, segment)
  • Moments are encrypted; notifications do not reference plaintext content
  • Users can disable notifications entirely in settings

12. Implementation Approach

Phase 1: Infrastructure (Weeks 1–2)

  • Set up push notification service (Firebase Cloud Messaging for iOS)
  • Build notification scheduling system
  • Implement opt-out/settings UI
  • Add analytics event logging

Phase 2: User Segmentation (Weeks 2–3)

  • Build logic to identify funnel stage (A, B1, B2, C, D) per user
  • Store segment assignment in database

Phase 3: Generic Notifications (Weeks 3–4)

  • Write generic notification templates for each segment
  • Test delivery, timing, click behavior
  • Measure baseline CTR and conversion

Phase 4: Timing Optimization (Weeks 5+)

  • Analyze when users typically open app
  • Schedule notifications for optimal time
  • A/B test: fixed time vs. smart time
