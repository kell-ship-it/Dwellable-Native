How the free/paid AI split actually works

A plain-language walkthrough — updated July 5, 2026 with a corrected capacity model (a real error was caught and fixed) plus real measured numbers
Correction notice: An earlier version of this document mislabeled OpenAI's "Batch queue limit" (a separate, unrelated limit for OpenAI's asynchronous Batch API) as if it were a real-time daily token cap for normal chat usage. That mistake understated Tier 1's real capacity by roughly 4x. This version is corrected: the real constraint is Tier 1's actual daily request cap (10,000 RPD) combined with how many API calls one full loop takes (6). The corrected story is better news than before, not worse.

1. What is a "loop"?

A loop is one full trip through the app for one moment — start to finish: capture, 3 reflection turns, prayer, journal. We ran this exact loop live 4 times to find a reliable number.

Runs 2, 3, and 4 all used the refined prompt (the one that has the assistant invite prayer itself right after the 3rd reflection turn, instead of a separate call). They landed within 4% of each other — 4,802, 4,691, 4,622 — a genuinely stable, repeatable number, not noise. Average: 4,705 tokens per loop, across 6 real API calls. Every one of these numbers is confirmed twice — once from OpenAI's own usage API, once from summing the real per-call numbers straight from the transcripts. Real cost split: ~4,402 input tokens + ~303 output tokens per loop, on average.

6. Worst case: what if someone actually maxed out the daily limit?

A natural follow-up question: how much could Tier 1 or Tier 2 cost on the single worst day, if something (a bug, an attack, a runaway loop) tried to use the absolute maximum allowed? The corrected math here is a real risk to plan around — these worst-case numbers are meaningfully higher than we first thought.

ScenarioMathApprox. cost/day
Tier 1, all-input flood (via TPM)200,000 TPM × 1,440 min = 288M input tokens$43.20
Tier 1, all-output flood (via RPD × max output)10,000 requests/day × 16,384 max output tokens/response = 163.84M output tokens$98.30
Tier 2, all-input flood (via TPM)2,000,000 TPM × 1,440 min = 2.88B input tokens$432.00
Tier 2, all-output flood (via TPM)2,000,000 TPM × 1,440 min = 2.88B output tokens$1,728.00

Tier 2's worst case ($1,728) actually exceeds its own $500/month spend cap in a single day — meaning the monthly budget cap, not the rate limit, is the real backstop there, and it shouldn't be relied on alone.

Tier 1Tier 2+
What stops runaway usage?Hits the 10,000 requests/day wall — blocked automatically, worst case ~$43-98/dayNothing, until the $500/month spend cap is hit — worst case could reach $1,728/day theoretically
The real takeaway isn't a dollar figure — it's a missing safety net. At Tier 1, a runaway bug is naturally bounded to well under $100/day by the request cap itself. At Tier 2, that automatic brake disappears — the only thing standing between normal usage and burning the full $500/month budget in one afternoon is whatever budget alerts or hard spend limits we configure ourselves. Worth setting up before ever moving to Tier 2, not after.

7. The bottom line

Getting all 1,000 first-time users all the way through capture, 3 reflection turns, a prayer, and a journal entry costs about $0.82, total — and, corrected, every single one of them can be served the same day on Tier 1 alone, no Tier 2 upgrade needed for this scenario. The free Groq tier covers a small slice of that for nothing; the rest costs less than a tenth of a cent per person on GPT-4o mini. The 4,705-token benchmark is backed by three consistent, repeated live tests. The one real risk worth planning for isn't normal usage — it's uncontrolled/runaway usage, which is why the safety controls above (per-user limits, output caps, budget alerts) matter before scaling past Tier 1.
