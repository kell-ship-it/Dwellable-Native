Pillar 4: Journal Synthesis — Skeleton Summary

What We're Building

Pillar 4 (Journal Synthesis) transforms captured conversations into meaningful journal entries via LLM synthesis, with optional guided prayer and user-customizable moods/tags. Users can re-engage, add reflections, and reflect on their spiritual journey over time.

1
Capture Complete

User finishes conversational moment capture (Pillar 1). Taps "Done" to signal completion.

2
Confirmation Screen (Option A)

App shows: "Captured your moment! We briefly talked about [x, y, z], would you like to pray over these things?" Displays key themes extracted from conversation. Primary CTA: "Pray About This" (routes to Pillar 3). Secondary: "Skip" or "View Moment".

3
Guided Prayer (v1)

User enters Pillar 3 (Soaking) guided prayer flow focused on the captured moment. Prayer is guided (v1), freeform prayer deferred to v2. Prayer attaches to journal entry.

4
Journal Synthesis (Background)

LLM generates full journal entry from conversation transcript. Output: auto-generated title + 2-3 paragraph body + suggested moods. Synthesis runs async in background while user prays.

5
Dwelling Place Tab

User sees generated journal entry in "Dwelling Place" tab (not "Analysis" tab). Can view original conversation in "Entry" tab. Journal is editable post-synthesis.

6
Editing & Customization

User can: select/modify mood tags from predefined list, add additional photos (camera or upload), edit any journal fields. Delete capability included. Re-engagement: can add reflections (encourages re-capture for new moments).

Journal Artifact Structure

Journal Entry { id: unique_identifier date_created: timestamp title: auto_generated_headline (LLM) body: full_journal_text (2-3 paragraph synthesis) moods: [tag1, tag2, tag3] (user-selected from predefined palette) photos: [photo_id_1, photo_id_2, ...] (user can add/remove) prayer_reference: prayer_id (links to attached prayer artifact) original_moment_id: moment_id (links back to Pillar 1 conversation) edited: boolean (tracks post-synthesis modifications) deleted: boolean (soft delete capability) }

Tools & SDKs Required

Gemini 2.0 Flash / Mistral 7B

LLM for journal synthesis. Generates title + body from conversation transcript. MVP: Gemini (free tier). Post-MVP evaluation: Mistral or Claude for quality/cost trade-offs.

Design Exploration & Rejected Approaches

Two-Tab Architecture (Entry + Dwelling Place): Preserves original conversation (Entry tab, raw transcript) while providing synthesized reflection space (Dwelling Place tab). Users see both contexts. Rejected: hiding conversation behind synthesis (loses original dialogue). Rejected: single journal view with embedded conversation (cluttered, reduces focus on reflection).
Confirmation Screen Placement: Appears AFTER capture, BEFORE prayer. Shows app understood the moment ("talked about X, Y, Z"), invites prayer. This creates natural transition from capture → prayer → journal. Rejected: skipping to journal immediately (less contemplative, loses prayer moment). Rejected: prayer only after journal (user already read synthesis, less open to reflection).
Moods/Tags Unified: Single predefined palette (emotional + spiritual moods: Reflective, Conflicted, Exhausted, Hopeful, Loved, Prayerful, etc.). Rejected: separate moods (emotional) vs tags (topical). For spiritual journaling, emotional state IS the spiritual mood—keeping them unified reduces mental overhead and keeps interface simpler.
LLM Synthesis Over User-Written Journals: App generates journal from conversation rather than asking user to write journal manually. Rationale: conversation is already deeply reflective; synthesis reframes it as journal. User can edit post-synthesis. Rejected: requiring user to write (adds friction, creates blank-page anxiety, duplicates reflection work). Rejected: only showing conversation (lacks contemplative synthesis/reframing).
Post-Synthesis Photo Upload (v1): User can add/remove photos after journal is created. v2 will add GAI (Generative AI image descriptions) for photos. Rejected: requiring photo at capture time (not all moments are visual). Rejected: no post-synthesis photo editing (limits flexibility).

Locked Decisions

Confirmation Screen Option A: "Captured your moment! We briefly talked about [x, y, z], would you like to pray over these things?" — Specific, warm, shows app listened. Requires theme extraction from conversation (LLM-powered), but value justifies complexity.
Prayer Integration (v1): Guided prayer only in v1 MVP. Prayer attaches to journal. Designer determines whether prayer becomes separate artifact with reference, or note field on journal (deferred to designer).
Tab Naming: Entry + Dwelling Place: "Entry" = raw conversation. "Dwelling Place" = synthesized journal. Naming is intentional, theologically grounded (dwelling = abiding, contemplation, presence).
Encryption: AES-256-GCM (Same as Pillar 2): Conversation transcript + journal body encrypted at rest on device + in transit. Same master key derivation (Argon2id). Transcript not editable, not searchable on server (client-side search only). Offline-capable.
Journal Editability (Detail View Only): Users edit journal in detail view (not on list cards). Can modify moods/tags, add/remove photos, edit journal text post-synthesis. Edit tracking enabled (note if user has modified journal).
Delete Capability: Users can delete journal entries (soft delete supported). Encourages re-capture if they want to refresh/re-engage.
Linking to Pillar 1: Journal entry stores reference to original moment (original_moment_id). User can navigate back to Pillar 1 conversation from Dwelling Place.
Re-engagement: Users can add reflections to old journal entries. Re-prayer deferred to backlog (encourages fresh capture instead). Fresh captures create new journal entries (preferred over modifying old entries).
LLM Synthesis Output: Title (auto-generated, 4-6 words) + Body (2-3 paragraph narrative prose, not structured sections) + Suggested Moods (2-3 tags, user can override). Tone: contemplative, personal, affirming. Mirrors user's language but reframes as spiritual reflection.
Moods/Tags: Predefined Palette: User-selectable from spiritual/emotional palette (Reflective, Conflicted, Exhausted, Hopeful, Loved, Prayerful, Grieving, Grateful, etc.). Limit 2-3 per journal. Searchable across library.
Photo Management v1: User can add photos via camera or photo library after journal synthesis. Can remove photos. v2 will add GAI descriptions. No photo required for synthesis (text-only moments are valid).

Tentative / TBD

Synthesis Latency UX: Deferred until happy path fully finalized. Options: silent background work vs loading spinner vs confirmation screen that shows progress. Recommend confirmation screen shows "Generating your journal..." while prayer completes.
Prayer Artifact Storage: Designer to determine: separate prayer artifact with reference to journal, OR note field attached to journal. Both approaches valid; designer chooses based on UX patterns.
Empty Capture Handling: Deferred until all pillars have happy paths. Options: (1) mandate text, (2) accept photo-only + guided prompts for depth, (3) hybrid with quality threshold. Will decide after seeing full capture flow context.
Offline Synthesis Capability: MVP: cloud-based synthesis required (Gemini/Mistral). v2+: on-device synthesis (Mistral 7B quantized or equivalent) for true offline support. Architecture to be designed in v2.
LLM Provider Decision: MVP locked on Gemini 2.0 Flash (free tier, sufficient quality). Post-MVP tournament: evaluate Mistral vs Claude vs OpenAI for synthesis quality, cost, latency. Decision after Phase 2 Beta feedback.

Open Questions (Deferred Until Full Pillar Mapping)

  • Synthesis Latency UI: Should confirmation screen show progress ("Generating journal...") or is silent background work sufficient?
  • Error State Handling: If synthesis fails, fallback to Entry tab only? Retry? Manual journal entry?
  • Empty Capture Handling: Photo-only vs text-only vs both? Quality thresholds before synthesis?
  • Journal Search Scope: Should user be able to search journal text + conversation transcript together, or separately?
  • Reflection Limits: Can users add unlimited reflections to old journal entries, or should we encourage fresh captures?
  • Export/Sharing (v2+): Should journals be exportable as PDFs, shareable as text, embeddable in community?

Success Metrics (Phase 2 Beta)

  • Journal Creation Rate: >80% of captured moments result in journal entries (completion rate through full synthesis flow)
  • Synthesis Quality: >75% user satisfaction with auto-generated journal titles + bodies (rated via post-journal prompt or editing engagement)
  • Prayer Engagement: >60% of users pray about captured moments (via confirmation screen CTA)
  • Re-engagement: >40% of users add reflections to old journal entries or re-capture moments
  • Mood Tag Customization: >70% of users modify suggested moods (indicates personalization)
  • Photo Addition (Post-Synthesis): >30% of users add photos after journal synthesis
  • Synthesis Latency: <5 seconds average time from prayer completion to Dwelling Place visible
  • Editing Engagement: >50% of users edit journal text post-synthesis (indicates ownership + depth)

Integration Points with Other Pillars

Pillar Integration
Pillar 1 (Capture) Journal entry links back to original moment. User can navigate between Entry (conversation) and Dwelling Place (synthesis). Conversation provides rich context for synthesis.
Pillar 2 (Security) Conversation transcript + journal body encrypted at rest + transit (AES-256-GCM). Same key derivation as Pillar 2. Full E2E encryption.
Pillar 3 (Soaking) Confirmation screen routes to Pillar 3 guided prayer. Prayer attaches to journal. Prayer becomes contemplative response to synthesized journal.
Pillar 5 (Patterns/Search) Journal entries searchable via full-text (client-side), filterable by moods/tags, browsable chronologically. Supports pattern recognition across journal library.
Pillar 6 (Community) Post-MVP: journal entries can be shared with trusted people. v1 focus on personal reflection; v2+ sharing/collaboration.
Pillar 7 (Notifications) Notifications can nudge users to journal about past moments, encourage re-engagement, or remind to review synthesis.
