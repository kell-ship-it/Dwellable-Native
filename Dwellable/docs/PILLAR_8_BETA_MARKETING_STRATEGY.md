**Founder:** Kell Golden | **Status:** 🔄 **DESIGN IN PROGRESS** | **Updated:** May 10, 2026

## Design Summary

Pillar 8 enables the transition from Phase 1 personal dogfooding → Phase 2 closed beta with targeted user cohorts. This pillar includes self-signup flow for beta users, cohort management (tracking, segmentation, cohort-based rollout), feedback collection (in-app surveys, analytics, structured interviews), and community engagement (Discord, email updates).

The core principle: **Validate dwelling behavior at scale and celebrate spiritual formation.** Measure whether Dwellable achieves its North Star: users notice and dwell on God's presence across their entire life.

## Core Concept

**Measure what matters: Dwelling, not downloads.**

Traditional app metrics (DAU, MAU, retention) miss the point. Dwellable measures:
- **Weekly Active Reflections (WAR):** % of users who dwelled on moments this week
- **Dwelling Depth:** Did user pray? Reflect? Return multiple times?
- **Formation Perception:** Did user report "noticing God more"? Seeing patterns?
- **Community Engagement:** Did user share in Discord? Participate in interviews?

This is validation that Formation Intelligence works.

## Happy Paths (7 Main Paths)

### Path 1: Beta User Self-Signup

**Scenario:** A user hears about Dwellable (social media, word-of-mouth, church community) and wants to join Phase 2 beta.

1. **User Visits Signup URL** → www.dwellable.app/beta or landing page
2. **See Beta Pitch** → Clear copy: "Dwellable is for capturing and dwelling on God's presence. We're in Phase 2 beta. Join us."
3. **Tap Apply** → User taps "Join Beta" button
4. **Fill Signup Form** → Name, email, main practice, device, why interested
5. **Submit** → User submits form
6. **Waitlist Confirmation** → "Thanks for your interest! We'll email when a spot opens."
7. **Email Confirmation** → User receives beta cohort info and next steps
8. **Beta Access Granted (Staggered)** → User receives TestFlight link + onboarding email
9. **Install & Launch** → User installs app and enters Pillar 0 onboarding

### Path 2: Cohort Enrollment & Tracking

**Scenario:** Beta manager assigns users to cohorts for staggered rollout and A/B testing.

1. **Admin Dashboard** → Manager views signups
2. **Segment Users** → Categorize into cohorts:
   - **Cohort A (Consistent Reflectors):** Daily journalers
   - **Cohort B (Selective Reflectors):** Occasional reflectors
   - **Cohort C (Control/Waitlist):** Not yet activated
3. **Assign to Cohort** → System auto-sends TestFlight invite
4. **Track Progress** → Per-cohort metrics: onboarding, capture, WAR, retention
5. **Staggered Activation** → Cohort A at T+0, B at T+1 week, C later
6. **Compare Results** → Identify which segment engages best

### Path 3: In-App Feedback Collection

**Scenario:** User sees optional feedback prompts during app usage.

1. **After First Capture** → "How was your first moment capture?" (optional)
2. **After First Dwelling** → "Did reflecting help you notice God's presence?" (Yes/No/Neutral + comment)
3. **Weekly Check-In** → "What's working? What's missing?" (free text)
4. **Feedback Submitted** → Data sent to analytics platform
5. **User Sees Impact** → Email: "Your feedback helped us improve..."

### Path 4: Structured Interview Process

**Scenario:** Manager conducts 1:1 interviews with users every 2 weeks.

1. **Recruit Interviewees** → Email: "Can we chat about your experience? 20 minutes?"
2. **Schedule Interview** → User books time slot
3. **Interview Script** → Standard questions about capture, dwelling, spiritual impact
4. **Record Notes** → Document key insights
5. **Aggregate Findings** → Themes emerge across interviews
6. **Share Learnings** → Weekly summary of insights to product team
7. **Iterate Product** → Use findings to refine Pillar design

### Path 5: Community Engagement (Discord)

**Scenario:** Users want to discuss Dwellable, share insights, and build community.

1. **User Invited to Discord** → Onboarding email includes Discord invite
2. **Join Server** → See channels: #announcements, #feedback, #moments, #help
3. **Participate** → Share moments, ask questions, suggest improvements
4. **Manager Monitoring** → Team monitors #feedback and #help
5. **Iteration Loop** → Feature requests feed into Phase 2+ planning

### Path 6: Email Engagement Campaign

**Scenario:** Regular emails keep users informed and invested.

1. **Welcome Email (Day 1)** → Celebrates signup, explains roadmap
2. **Onboarding Email (Day 3)** → "Your first capture is huge. Here's how to dwell..."
3. **Weekly Digest (Friday)** → Stats + feature highlight + Discord invite
4. **Feature Highlight (Bi-weekly)** → "This week we shipped..."
5. **Feedback Request (Every 2 weeks)** → "Help us improve: 2-min survey"
6. **Interview Invite (Periodic)** → "We'd love to chat about your experience..."
7. **Cohort Milestone (End of Beta)** → "Here's what you helped us learn..."

### Path 7: Metrics Dashboard & Reporting

**Scenario:** Team reviews weekly metrics to track Phase 2 success.

1. **Weekly Review Meeting** → Team views dashboard
2. **Key Metrics Tracked:**
   - Activation: # signups, # installs, # first captures
   - Engagement: WAR (weekly active reflections), session length
   - Dwelling: # journal reads, # prayers, # theme engagements
   - Cohort breakdown: above metrics per cohort
   - Support: # bugs, # questions, resolution time
3. **Analyze Trends** → Is WAR hitting 40-50% target? Which features drive engagement?
4. **Iterate** → Use findings to prioritize Pillar refinement
5. **Communicate** → Weekly summary to team, monthly to beta community

## Locked Decisions

1. ✅ **Closed Beta:** Invite-only (staggered rollout), not open to public
2. ✅ **Cohort Structure:** Consistent reflectors vs selective reflectors vs control
3. ✅ **Feedback Collection:** Analytics + surveys + interviews (quantitative + qualitative)
4. ✅ **Community Platform:** Discord for beta engagement
5. ✅ **Email Cadence:** Weekly digest + bi-weekly highlights + periodic interviews
6. ✅ **Success Metric:** Primary = WAR 40-50% by week 8; secondary = retention, dwelling depth
7. ✅ **Cohort Size:** 20-30 users per cohort, expand based on stability
8. ✅ **Interview Frequency:** ~5-10 users/week for structured 1:1s

## Data Model & Metrics

### BetaUser Structure

```swift
struct BetaUser: Codable {
    let id: String                              // UUID
    let email: String
    let name: String
    let signupDate: Date
    let cohort: String                          // "A", "B", "C"
    let invitedAt: Date?                        // TestFlight invite sent
    let acceptedAt: Date?                       // When activated
    let firstCaptureAt: Date?                   // First moment captured
    let interviewScheduled: Date?               // Next interview date
    let notes: String?                          // Manager notes
    let engaged: Bool                           // Currently active
}
```

### Key Metrics (Per Week, Per Cohort)

| Metric | Definition | Target |
|--------|-----------|--------|
| **WAR** | % of users who engaged with ≥1 dwelling/prayer/reflection this week | 40-50% by week 8 |
| **Onboarding Completion** | % of users finishing P0 onboarding | >80% |
| **First Capture Rate** | % of users capturing first moment | >70% by day 3 |
| **Session Length** | Avg minutes per session | >5 min |
| **Dwelling Depth** | # of times user returns to same moment | >2x per moment |
| **Prayer Engagement** | % of users praying via Pillar 3 | >40% |
| **Theme Engagement** | % of users interacting with detected themes (P7) | >50% |
| **Week 1 Retention** | % of users returning day 2-7 | >70% |
| **Week 4 Retention** | % of users returning week 2-4 | >50% |
