Pillar 5: Design Clarifications & Decisions

Answer key design questions. Lock final decisions for Phase 2.

Path 1: Edit Timestamps
Your Question: "What's the risk of not enabling time stamp revisions?"

Should we track when edits were made? Timestamps create an audit trail of how the user refined their journal. Risks of not tracking: user can't remember when they edited, no history of evolution. Risks of tracking: added complexity, more metadata to encrypt.
Track edit timestamps — show when each edit was made (audit trail)
Don't track timestamps — simple, MVP (recommended)
Path 2: Mood Mutability & Formation Intelligence
Your Insight: Moods are training data for the user's spiritual journey LLM. When user edits moods, they're telling Formation Intelligence "I was wrong about that day's spiritual state." This retrains the model's understanding.

Three Approaches:
Option A: Locked at Creation — Moods set at journal creation, immutable. Preserves authentic historical record. User sees "⚠️ Editing moods retrains your spiritual journey model" warning if they try to change.
Option B: Freely Editable — User can change moods anytime. Formation Intelligence treats all mood states equally. Simpler UX, less friction.
Option C: Auto-Generated + Override — Formation Intelligence infers moods from transcript; user can accept or override. User can't change after journal is created (hybrid of A+B).
Path 3: Photo Captions
Your Question: "Will captions per photo conflict with the content of the journal entry?"

Good UX concern. If each photo has a caption AND the journal body discusses the photo, there's redundancy. Options: keep captions lean (1 sentence), optional, or skip captions entirely for MVP.
Include captions — optional, brief (one sentence). Searchable.
Include captions — mandatory, full text. Searchable.
Skip captions for MVP — lean, simple. User photo metadata only.
Path 7: Archive/Delete Terminology & Flow
Your Note: "Archive, Delete (30 days to recover before fully deleted)"

Clarifying the soft-delete recovery flow. User perspective: tap delete → item goes away → recoverable for 30 days → after 30 days, gone forever.
Single "Delete" button — soft delete, 30-day recovery, then permanent purge. (recommended)
"Archive" button (hide) + "Delete" button (soft delete). Two-step.
"Delete" shows confirmation: "Recoverable for 30 days. After 30 days, permanently deleted."
Text Formatting Scope for Phase 2

Lean rich-text editor — buttons for bold, italics, lists, links. No fonts/colors/sizes.
Plain text + markdown shortcuts — user types **bold**, *italic*, - list. No WYSIWYG.
Plain text only + line breaks. No formatting for MVP (defer to Post MVP).
Continue Chat with Prompts Post-Journal Creation?
Your Flagged Issue: "Dwellers wanting to continue conversation with prompts but are now in Journal mode."

Once journal synthesis happens, user transitions from conversation mode (Pillar 1) to journal viewing/editing (Pillar 5). Should we allow continuing the original conversation, or must the user start a new capture?
Option A: YES — Continue Conversation

✓ Pros

  • User can refine capture mid-stream
  • More flexible, natural workflow
  • Second prompt attempt feels unblocked

✗ Cons

  • Ambiguity: which prompts belong to which journal?
  • "Journal creep" risk — user keeps adding
  • UI complexity: parallel tabs/modes
  • Formation Intelligence confusion
Option B: NO — Conversation Ends at Journal Creation (MVP)

✓ Pros

  • Clear, simple flow
  • One mode at a time
  • Clear moment/journal boundaries
  • Formation Intelligence unambiguous

✗ Cons

  • More rigid UX
  • User must start new capture
  • Might frustrate mid-conversation users
Option A: YES — Allow continuing conversation after journal creation
Option B: NO — Conversation ends at journal creation (recommended for MVP)
