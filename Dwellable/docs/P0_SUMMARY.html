P0: Onboarding — Skeleton Summary

What We're Building

Pillar 0 (Onboarding) is the first-time user journey that takes spiritual seekers from discovery to their first captured moment, with personalization grounded in their intent.

1
Initial Decision Screen

Sign Up / Sign In choice. Returning users go to Sign-In. New users proceed to carousel.

2
Product Expectation Carousel (4 Cards)

Aspirational lifestyle imagery + spiritual tone. Each card weaves problem clarity, value clarity, education, and trust throughout (not 1:1 mapping).

Cards: Partnership with God | Hidden Private Moments | Capture → Reflect → Grow | Ready to dwell deeper?

3
Access & Identity Formation (Model 1: Embedded Progressive)

Display name → Intent question → Email/Password (no separate "Create Account" screen). Google/Apple IDPs available on Sign-In screen only (not in signup flow).

4
Intent Calibration + Personalized Promise

User selects 2-3 intents from list of 6. Gemini generates a personalized promise confirming Dwellable's understanding and outcomes.

5
Capture Screen

Embedded in onboarding. User captures their first moment (voice or text).

6
Post-Capture Celebration + Invitation to Soak

"Congratulations for your first entry." CTA: "Pray" / "Soak" (same experience, label TBD) or "See my moment." Design indexes heavily toward Pray/Soak.

Design Exploration & Rejected Approaches

Signup Model Evolution: Model 2 (dedicated "Create Account" screen separate from Sign-In) was explored but rejected. Model 1 (Embedded Progressive) chosen because it feels more conversational and natural for first-time users—questions flow as part of the onboarding experience, not as a separate account creation step.
Email Validation Confirmation: Email confirmation gating (requiring user to click email link before account activation) was considered for MVP but deferred to v2. MVP prioritizes fast signup (email validated server-side, no manual confirmation required). Future version can add this security layer if needed.
IDP Placement: Google Sign-In and Apple Sign-In considered for both signup and sign-in flows. Rejected for signup carousel. Currently locked to Sign-In screen only—keeps signup lightweight, prioritizes password-based identity for security model, reduces complexity in first-time flow.
Reflection Prompts During Intent Selection (New): After carousel, users see 3 reflective prompts (e.g., "Think of a decision that didn't turn out how you hoped. What did you learn?") before committing intents. These help clarify intentions and preview what reflection feels like. Separate from P1 capture experience—this is intent calibration, not moment capture.

Locked Decisions

Signup Model: Model 1 (Embedded Progressive). No separate "Create Account" screen. Questions flow naturally as part of onboarding.
Demo Approach: Carousel cards with aspirational lifestyle imagery (not product UI). Spiritual tone (not explicitly Christian labels, but deeply spiritual language).
Intent List: 6 intents (Keep journaling habit, Deepen faith, Process emotions, Find peace, Understand God's voice, Practice gratitude). All deliverable in Phase 2 Beta MVP.
Reflection Prompts During Intent Selection: After carousel, users see reflection prompts (e.g., "Think of a decision that didn't turn out how you hoped. What did you learn?") to help clarify intents and preview what reflection feels like. Prompts can be refreshed. Helps users self-assess + builds confidence before committing intents.
Intent Lock: Intents are locked at signup (not editable later). Used for first-capture personalization only.
IDP Strategy: Google/Apple Sign-In available on Sign-In screen only (not in signup carousel flow). Hybrid approach: lightweight decision screen (Sign Up / Sign In) routes users to appropriate flow.
Phase 2 Beta Release: Option A — Phase 2 Beta fully complete with all 7 pillars → release to App Store as MVP (no staging or feature gates).

Tentative / TBD

Open Questions

  • Backlog tracking: Where should v2 items (like email validation) be tracked? BACKLOG.md or existing brainstorm doc?
  • PostHog configuration: What's the specific event schema for analytics? (e.g., event names, properties, user identity)
  • Promise screen design: Should personalized promise be a full-screen card, inline with other copy, or embedded in the "ready to capture?" prompt?
  • Intent CRUD: If intents are locked at signup, do we need an admin interface to manage the intent list as it grows post-MVP?
  • Error handling: What happens if Gemini promise generation fails? Show static fallback, retry, or graceful skip?
  • Accessibility: WCAG compliance for carousel (screen readers, keyboard nav, color contrast)?

Success Metrics (from P0)

  • CTR (Click-Through Rate): % of users who start carousel and complete signup
  • Signup Completion Rate: % of users who reach intent selection
  • Time-to-First-Capture: Average time from signup to first moment captured
