Pillar 1: Capture — Skeleton Summary

What We're Building

Pillar 1 (Capture) is the low-friction moment recording system, enhanced for phase 2 beta with conversational text interface, optional prompts, and post-capture completion flow.

1
Capture Initiation Screen

Toggle engine (voice/text icons) + large microphone button + carousel of optional prompt starters. Seamless switching between modes.

2a
Voice Capture Flow

Record with real-time waveform visualization + timer. On-device transcription via Speech Framework. Validate minimum 0.5s audio, reject silence.

2b
Text Capture Flow (New for Phase 2)

Message-style chat interface. System prompts appear as optional starters (left-aligned). User responses in chat bubbles (right-aligned). Send button at bottom. Conversational, not form-like.

3
Post-Capture Processing

Moment saved locally (encrypted via pillar 2). LLM generates auto-headline. Queued for sync when network available.

4
Post-Capture Completion Screen

✓ Moment saved confirmation. Display auto-generated headline + preview text. Prompt: "Ready to reflect deeper?" CTAs: "Pray on This Moment" (primary, indexes toward pillar 3), "View My Moment", "Capture Another".

Design Exploration & Rejected Approaches

Text Capture Interface Evolution: Form-based text input (similar to current Build 107 TypeFlowView) was initially considered. Rejected in favor of message-style chat bubble interface because chat feels conversational and invitational, not form-like. Users engage with system prompts naturally, can ignore them, or start fresh.
Prompt System Evolution: Initial approach: static prompt carousel shown at initiation, user could swipe/tap. Evolved to conversational system: 1 prompt upfront at capture initiation, then 1 prompt after each user response (voice or text), continuing naturally throughout capture. This mirrors human conversation better than carousel alone.
Reflection Prompts Placement: Reflection prompts are intentionally NOT in P1 (capture) as continuous dialogue. Instead: 3 reflection prompts appear in P0 (onboarding, intent clarification phase) + conversational prompts during capture (P1) are different—they guide reflection on the moment itself. Separation keeps phases distinct: P0 is "who are you?", P1 is "what happened?", P3 is "what does this mean?"
Completion Screen Routing: Considered: different CTAs based on capture type (voice vs text). Rejected: single primary CTA ("Pray on This Moment") for both. Keeps UX consistent, indexes all users toward P3 soaking equally.

Locked Decisions

Voice-First + Text Fallback: Voice primary (100% phase 1 adoption proven). Text is secondary but equal capability. Both routes to same completion flow.
On-Device Transcription: Speech Framework (Apple native). Privacy-first, offline-capable, no API keys exposed.
Text Message Interface: Chat bubble style for text capture. Conversational, invitational (not form-like). System prompts optional starters.
Optional Prompts: Prompts are never mandatory. Users can ignore carousel and start fresh. Soft invitation to reflection.
Post-Capture Completion Screen: Show moment + headline, ask "Ready to reflect deeper?", index heavily toward "Pray on This Moment" CTA (pillar 3 soaking).
Integration with Pillar 0: First capture embedded in onboarding flow. Completion screen leads to post-entry celebration (pillar 0 step 4b).
Encryption-Ready: All moments prepared for E2E encryption (pillar 2). No changes to capture logic; encryption happens at sync layer.
Intent-Based Context Prompts: Prompts shown on capture screen are personalized based on user's selected intents from pillar 0 onboarding. Provides contextually relevant guidance for reflection (e.g., user selected "Deepen faith" → prompts about God's presence; selected "Process emotions" → prompts about feelings). Makes capture more relevant + invitational.
Conversational Prompt System (During Capture): 1 reflection prompt shown upfront at capture initiation. After user responds (voice transcribed or text entered), another prompt appears. Continues conversationally throughout capture. Applied to both voice + text flows. May gate after N prompts per session (premium feature).

Tentative / TBD

Prompt Content Source: MVP uses static/generic prompts in carousel. Next version: prompts personalized based on past conversations + detected themes (requires narrative continuity from phase 2+).
Auto-Generated Headline Quality: LLM-generated headlines locked for direction. Exact quality depends on Gemini integration. May need human refinement loop in beta.
Prompt Carousel Behavior: Should prompts auto-advance, require swipe/tap, or randomize each session? UX refinement during design phase.
Text Message Visual Refinement: Chat bubble styling locked conceptually. Color scheme, animations, spacing refined during design handoff.

Open Questions

  • Prompt Engagement Tracking: Should we log which prompts users engage with vs ignore? (Informs next-version personalization strategy)
  • Completion Screen Variants: Should CTA buttons differ based on capture type (voice vs text)? E.g., voice → "Pray on This", text → "Add more context"?
  • Multi-Prompt Capture: Can users capture multiple moments in rapid succession? Any rate limiting or cooldown?
  • Prompt Freshness: How often should prompt carousel rotate? Per session? Per day? Random?
  • Headline Customization: Should users be able to edit auto-generated headlines immediately on completion screen, or defer to pillar 4 (editing)?
  • Audio File Cleanup: Where/when are temporary audio files deleted after transcription?
  • Empty Moment Handling: If user captures but doesn't add "sense of Lord" or other metadata, what's the minimum valid moment?

Success Metrics (Phase 2 Beta)

  • Capture Adoption: >95% of daily active users capture at least 1 moment/week
  • Voice Quality: >95% transcription accuracy in normal environments
  • Text Engagement: >60% of users use text capture at least once (vs voice-only)
  • Prompt Engagement: >50% of users tap a prompt starter (vs ignoring carousel)
  • Completion Rate: >85% of captured moments reach post-capture screen (not abandoned)
  • Time-to-Save: <30 seconds average from capture initiation to completion screen
  • Headline Quality: >70% user satisfaction with auto-generated headlines (rated in pillar 4 editing)

Integration Points with Other Pillars

Pillar Integration
Pillar 0 (Onboarding) First capture happens in onboarding flow. Completion screen leads to post-entry celebration.
Pillar 2 (Security) All moments encrypted before sync. Capture logic unchanged; encryption at sync layer.
Pillar 3 (Soaking) Completion screen CTA "Pray on This Moment" routes to pillar 3 prayer/prompts flow. Captured moments feed rich context synthesis.
Pillar 4 (Editing) Auto-generated headlines editable post-capture. Users can refine, re-tag, add mood in editing flow.
Pillar 5 (Search) Captured moments searchable via full-text search, calendar filters, tag filters.
Pillar 6 (Menu Bar) Create tab routes to capture screen. Captured moments appear in Today/Entries tabs.
Pillar 7 (Notifications) Notifications nudge users to capture. Capture counts inform engagement segmentation.
