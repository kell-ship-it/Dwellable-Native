Automated Testing Scenarios (I can write these as code tests)

These are scenarios that are better tested programmatically via XCUI tests, unit tests, or API integration tests. I can write these tests to run automatically and verify app behavior consistently.

CATEGORY A: API & Backend Integration (8 scenarios)

Verify API contracts, database operations, and Supabase integration

  • A.1 User registration API — POST /auth/signup with valid/invalid emails, verify responses and token generation
  • A.2 Moment save API — POST /moments with various payloads, verify Supabase table receives data correctly
  • A.3 Moment fetch API — GET /moments?userId={id}, verify returns correct moments in correct order
  • A.4 Audio upload API — Upload .m4a file to Supabase Storage, verify file path stored in database
  • A.5 Audio retrieval API — GET /moments/{id}/audio, verify returns correct audio file with proper MIME type
  • A.6 Delete moment API — DELETE /moments/{id}, verify moment removed from database and audio deleted from storage
  • A.7 Batch sync API — POST /sync with multiple pending moments, verify all sync in one request
  • A.8 JWT token refresh — Verify expired token automatically refreshes, request continues without interruption

CATEGORY B: Database & RLS Policies (6 scenarios)

Verify database structure, Row-Level Security, and data isolation

  • B.1 RLS: User can only read own moments — Create user A with moments, verify user B cannot read user A's data even with direct DB query
  • B.2 RLS: User can only write to own moments — Verify user cannot insert moment with another user's ID
  • B.3 Cascade delete: Audio files — When moment is deleted, verify audio file is also deleted from storage
  • B.4 Data validation: Timestamps — Verify created_at and updated_at timestamps are correct, updated on save
  • B.5 Data validation: Text encoding — Insert moments with UTF-8, emoji, special chars, verify database stores and retrieves correctly
  • B.6 Null handling: Optional fields — Verify optional fields (sense_of_lord, audio_url) can be null without errors

CATEGORY C: Offline Sync & Concurrency (6 scenarios)

Verify offline queue logic, sync deduplication, and concurrent operations

  • C.1 Offline queue enqueue — Add moment to sync queue, verify stored in UserDefaults/local storage
  • C.2 Offline queue dequeue — Trigger sync, verify queue is emptied after successful sync
  • C.3 No duplicate syncs — Add moment to queue twice, trigger sync, verify moment only synced once (not duplicated)
  • C.4 Sync order preservation — Queue 3 moments (A, B, C), trigger sync, verify all sync in order added
  • C.5 Concurrent writes (different moments) — Save 2 different moments in quick succession, verify both save without errors
  • C.6 Concurrent edit + sync — Edit moment while sync is happening, verify no data corruption

CATEGORY D: Error Handling & Recovery (7 scenarios)

Verify app handles failures gracefully and recovers cleanly

  • D.1 Network timeout during save — Simulate network timeout, verify moment goes to offline queue, not lost
  • D.2 Invalid response from API — Return malformed JSON from API, verify app handles error and doesn't crash
  • D.3 Storage full during audio upload — Simulate out-of-storage error, verify graceful error message to user
  • D.4 Transcription model load failure — WhisperKit fails to load, verify user sees error and can retry
  • D.5 Corrupted audio file — Feed invalid .m4a file to transcriber, verify rejects with error (no crash)
  • D.6 Database connection loss — Lose Supabase connection mid-sync, verify graceful fallback to offline queue
  • D.7 Transcription timeout — If transcription takes > 5 minutes, verify timeout error is shown

CATEGORY E: Edge Cases & Data Integrity (7 scenarios)

Verify app handles unusual inputs and preserves data integrity

  • E.1 Empty transcription (0 words) — WhisperKit returns empty result, verify rejected with error message
  • E.2 Single-word transcription — Very short phrase ("yes"), verify rejected (min 2 words)
  • E.3 Transcription with [BLANK_AUDIO] marker — WhisperKit returns text + [BLANK_AUDIO], verify marker stripped cleanly
  • E.4 Unicode/emoji in transcript — Transcription includes emoji or international chars, verify database stores and retrieves correctly
  • E.5 Very long transcript (10,000+ chars) — Save moment with very long text, verify no truncation or corruption
  • E.6 Null/empty optional fields — Save moment with sense_of_lord = null/empty, verify saves without error
  • E.7 Duplicate save (same content twice) — User saves same moment twice, verify second save treated as new moment (not overwrite)

CATEGORY F: Performance & Resource Management (6 scenarios)

Verify app performs efficiently and doesn't leak resources

  • F.1 Memory usage during 10-min recording — Monitor memory during 10-minute recording, verify no memory leak, peak under 200MB
  • F.2 CPU usage during transcription — Monitor CPU during WhisperKit transcription, verify efficient (not pegging at 100% for extended periods)
  • F.3 List performance with 100+ moments — Create 100+ moments in database, verify list scrolls smoothly without lag
  • F.4 Sync performance with large queue — Queue 20 moments for sync, verify all sync in under 30 seconds
  • F.5 Audio file cleanup after sync — After successful sync, verify temporary audio files are deleted from device storage
  • F.6 Local storage bloat prevention — After syncing offline moments, verify local queue is cleared to prevent bloat
