Testing Guide — Plain English Edition

Phase 1: Offline Support (5 tests)

Can you capture moments and save them when you don't have WiFi? When the internet comes back, does the app automatically send those moments to the database?
Why this matters:
  • Users will be capturing moments in random places (church, hiking, car) where WiFi isn't always available
  • We can't ask them to stay on WiFi — the app must work offline
  • The moment should save locally, and sync automatically when they get internet back

Phase 2: Authentication (6 tests)

Does login work correctly? Can you log in, stay logged in, and log out?
Why this matters:
  • Users need a secure way to sign in and access only their own moments
  • If login is broken, nothing else works
  • If the app logs you out randomly, users will get frustrated

Phase 3: Moment Operations (5 tests)

Can you create a moment by recording your voice? Can you type one instead? Can you see your moments in the list?
Why this matters:
  • The core feature is capturing moments
  • Users need to be able to use voice OR type
  • They need to see what they've captured and read it back

Phase 4: Network State Changes (6 tests)

What happens when WiFi drops while you're in the middle of doing something? Can the app recover gracefully?
Why this matters:
  • Users won't always have stable internet
  • WiFi might drop in the middle of saving a moment
  • The app should handle this without crashing or losing data

Phase 5: Data Persistence (6 tests)

If you force-quit the app or restart your phone, do you lose your data? Does everything stay safe?
Why this matters:
  • Users might accidentally close the app mid-operation
  • Their phone might die and restart
  • We can't lose their moments

Phase 6: Error Handling (4 tests)

If something goes wrong, does the app crash or handle it gracefully?
Why this matters:
  • Apps that crash on errors are terrible user experiences
  • Users need to see helpful error messages
  • The app should never become unusable

Phase 7: Performance (3 tests)

Does the app stay fast and responsive? Does it use too much memory?
Why this matters:
  • Slow apps feel broken to users
  • Apps that use too much memory drain battery
  • Users expect smooth scrolling and quick responses

Phase 8: UI/UX (5 tests)

Does the interface feel polished? Are buttons clickable? Does the keyboard work smoothly?
Why this matters:
  • A beautiful interface makes people want to use the app
  • Broken buttons or janky animations frustrate users
  • The app should feel professional and reliable

Phase 9 — Bug Fix Verification (3 scenarios)

These three tests verify that critical bugs found during testing have been fixed.
Why this matters:
  • B-003: Warnings in the build can hide real errors (clean code = reliable app)
  • B-007: Users need clear feedback when login fails (good UX = user trust)
  • B-008: Moments shouldn't disappear when offline (data reliability = user confidence)
# Scenario Expected Status Actions
9.1 B-003: No Build Warnings
Build the app and check Xcode console for warnings		 Xcode build completes with zero warnings (no duplicate ID issues)
What was broken: ForEach loops were creating duplicate IDs, causing Xcode warnings like "ID 5 occurs multiple times within the collection"
What was fixed: Replaced id: \.self with id: \.offset using enumerated() for unique position-based IDs
How to verify: Build the app (Product → Build) and check the Xcode console — you should see zero warnings
Notes:
9.2 B-007: Login Error Message Displays
Try logging in with wrong password		 Red error message appears: "Email or password is incorrect"
Valid test accounts (use correct password first, then try wrong):
  • Email: test@example.com   Password: password123 ✅
  • Email: kell@example.com   Password: test1234 ✅
What was broken: Login accepted ANY non-empty email/password without validating. Wrong passwords silently succeeded.
What was fixed: Added credential validation — app now checks if password matches the email account
How to verify:
  1. Enter test@example.com with password "wrongpassword"
  2. Tap Sign In
  3. You should see red error text: "Email or password is incorrect"
  4. Try again with correct password (password123) — should log in successfully
Notes:
9.3 B-008: Offline Moments Persist
Sign in online → go offline → create moments → come back online		 Original moments + new offline moments ALL visible (nothing disappears)
What was broken: When you went offline, previously-viewed API moments would disappear from the list. They'd come back when you went online again.
What was fixed: App now caches API-fetched moments to local storage, so they persist when offline
Step-by-step test:
  1. Sign in with test@example.com / password123 (WiFi ON)
  2. Wait for moments list to load — you should see existing moments (from API)
  3. Take note of how many moments you see (e.g., 5 moments)
  4. Turn OFF WiFi (Airplane mode or disable WiFi)
  5. Look at moments list — all 5 moments should STILL be visible ✅
  6. Create 2 new moments offline (voice or text)
  7. You should now see 7 moments total (5 API + 2 new) ✅
  8. Turn WiFi BACK ON
  9. Moments list syncs — you should still see all 7 moments ✅
  10. ❌ FAIL: If moments disappear at any point during this test, this fix isn't working

Phase 10 — Layer 1: 10-Minute Recording & Transcription (6 scenarios)

These six tests verify the Layer 1 features: 10-minute recording limit with 9-minute warning, background protection, mid-transcription dismissal handling, offline support, and temporary file cleanup.
Why this matters:
  • Recording limit prevents massive audio files and transcription timeouts
  • 9-minute warning gives users time to wrap up their thought
  • Background protection ensures no data loss if user locks device or switches apps
  • Temp file cleanup prevents disk space issues
  • Offline handling ensures transcription can continue in background
  • Mid-dismiss handling prevents transcription from hanging the app
# Scenario Expected Status Actions
10.1 9-Minute Warning
Record for 9+ minutes, watch for warning message		 Gold-colored message appears: "Hey, 60 seconds left in recording..."
How to test:
  1. Open CaptureView (tap to capture)
  2. Start recording (tap mic button)
  3. Let it record until timer reaches 9:00 minutes
  4. Watch for gold warning message at 9:00 mark
  5. Message should say: "Hey, 60 seconds left in recording. Feel free to add another moment to supplement this."
What to check:
  • Warning appears in gold color (matching theme.gold)
  • Warning shows only once (no flickering)
  • Warning appears at 9:00, not before or after
  • Console shows: "⏱️ [WARNING] Recording approaching 10-minute limit"
Notes:

  • Timer stops at 10:00
