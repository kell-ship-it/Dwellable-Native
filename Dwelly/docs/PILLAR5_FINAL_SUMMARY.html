Locked Decisions (7) ✓

1. Mood Mutability LOCKED
Decision: Option B — Freely Editable
Rationale: Moods are training data for Formation Intelligence. User edits signal spiritual growth/learning, not data loss. The delta is implicit—Formation Intelligence learns from all mood states.
Post-MVP: Capture intent with "Has mood changed?" prompt to enrich learning model.
2. Text Formatting LOCKED
Decision: Lean Rich-Text Editor (buttons)
Scope: Bold, italics, lists, links. No fonts, colors, sizes.
Reasoning: Self-explanatory (discovery), covers 80% of journaling needs, lean + powerful. Matches "very lean" Phase 2 requirement.
3. Photo Captions LOCKED
Decision: Skip captions for MVP
Reasoning: Lean/simple approach. Captions per photo could conflict with journal body content (redundancy risk). User photo metadata only for v1.
Future: Optional, brief captions (one sentence) post-MVP if needed.
4. Archive/Delete Flow LOCKED
Decision: Single "Delete" button — soft delete, 30-day recovery
UX: User taps delete → item goes away → recoverable for 30 days → after 30 days, permanently purged
Implementation: Flag `deleted: true`, store `deletedAt` timestamp, hide from Dwelling Place/search, recoverable from Trash
5. Edit Timestamps LOCKED
Decision: Don't track timestamps
Reasoning: Simple, MVP-appropriate. Marked as "edited" only, not when. Full edit history deferred to Post MVP.
Note: Journal stores `last_edited` for display but not granular version tracking
6. Journal Synthesis Timing LOCKED
Decision: After conversation closes
Reason: Clear boundary between Pillar 1 (Capture) and Pillar 5 (Journal). One conversation → synthesis → journal created.
Avoids: Ambiguity of which prompts belong to which journal.
7. Conversation → Journal Mapping LOCKED
Decision: 1:1 primary model
Clarification: Users can create one primary journal per conversation. Post-MVP: explore multiple journals from same conversation.
Reason: Simplicity for MVP, clear Formation Intelligence boundaries, unambiguous training data.
