Pillar 3: Soaking & Reflecting — Skeleton Summary

What We're Building

Pillar 3 (Soaking & Reflecting) transforms captured moments into guided spiritual prayer. Based on sentiment analysis of the captured moment (challenges vs celebration), users encounter a tailored CTA leading to personalized prayer powered by Rich Context synthesis (decrypted past moments + user intents analyzed by LLM).

1
Capture → Completion Screen

User completes moment capture (pillar 1). Completion screen displays: ✓ Moment saved, auto-generated headline, preview text. Primary CTA: "Pray on This Moment" (routes to pillar 3).

2
Sentiment Analysis + CTA Routing

LLM analyzes captured moment for emotional tone: challenges/struggles detected → "Let's pray about this." Celebration/gratitude detected → "Let's take a moment to thank the Lord for this." Single, contextually relevant CTA. User taps to continue.

3
Rich Context Synthesis (Background)

App decrypts past 20 moments (or last 7 days) in RAM. Gemini synthesizes: themes, spiritual patterns, user intents (from pillar 0). This context feeds prayer generation but is invisible to user (happens in background).

4
Guided Prayer

AI generates personalized prayer grounded in: current moment + sentiment tone + Rich Context + user intents. Prayer tailored to whether user is wrestling with challenges or celebrating God's goodness. User reads (non-interactive). Can save reflection or exit.

5
Optional Reflection Save

User can save post-soak reflection (optional). Reflection text encrypted, synced to Supabase, linked to original moment. No forced completion; low-friction exit anytime.

Design Exploration & Rejected Approaches

Sequential Prompts-First Flow Evolution: Initial design: Capture → 3 reflection prompts upfront → Prayer → Optional reflection save. This treated prompts as mandatory gatekeeping before prayer. Rejected in favor of current sentiment-based CTA routing: sentiment analysis determines single contextual CTA ("Let's pray about this" vs "Let's take a moment to thank the Lord for this") → Prayer → Optional reflection. Rationale: sentiment-driven CTAs feel more natural and respond to the actual moment, not a generic flow.
Reflection Prompts Relocation: Reflection prompts (3 total) were initially considered as part of P3 soaking flow. Relocated to P0 (onboarding intent clarification) and P1 (conversational during capture). P3 now has NO reflection prompts—only sentiment CTA → prayer → optional save. Cleaner separation: P0/P1 prompts help users articulate, P3 prayer helps users surrender/receive.
Prayer Variants Rejection: Multiple prayer versions per session (e.g., "short prayer" vs "long prayer") were considered to reduce choice paralysis via personalization. Rejected: single generated prayer per session. Rationale: one prayer per moment feels more intentional; user encounters what's offered rather than choosing. Less is more in contemplative experience.
Soaking Accessibility Scope (MVP): Full access to soaking from moments gallery/list was considered. Locked to post-capture only (MVP): users trigger soaking immediately after capture via "Pray on This Moment" CTA. Future phase: add soaking access from moments list. MVP keeps flow linear for first-time users.

Locked Decisions

Sentiment-Based CTA Routing: Moment analyzed for emotional tone (challenges vs celebration). Single, contextually relevant CTA presented: "Let's pray about this" (struggles) or "Let's take a moment to thank the Lord for this" (gratitude). Tailors prayer direction from the start.
Rich Context Window: Decrypt past 20 moments (or last 7 days, whichever is smaller) for synthesis. Prevents context window explosion while providing meaningful context.
Intents as Input: Gemini receives user's pillar 0 intents to personalize prompts + prayer (e.g., user selected "Deepen faith" → prayer emphasizes faith journey; "Process emotions" → prayer honors emotional landscape).
Reflection Prompts: 3 Total: AI generates 3 open-ended prompts per soaking session. Balanced—not overwhelming, enough for user choice.
Prayer: Single Generated Instance: One guided prayer per session (not variants). Intentional—user encounters what's offered, not choice paralysis. Prayer grounded in moment + context + intents.
Read-Only Experience: Prompts and prayer are non-editable. User reads, reflects, considers. Editing deferred to pillar 4 (for moments themselves). Contemplation over curation.
Optional Reflection Save: Post-soak reflection can be saved (encrypted, linked to moment) or discarded. No forced completion. Low-friction exit anytime.
Soaking Accessible Post-Capture Only: MVP: soaking triggered from post-capture completion screen ("Pray on This Moment" CTA). Not accessible from moments list/gallery. Keeps flow linear for first-time users.

Tentative / TBD

Reflection Storage & Discoverability: Should reflections be searchable/indexed like moments, or archived separately? Should reflections be visible in timeline with moments?
Text-to-Speech for Prayer: Should prayer be readable (current) or listenable (audio playback)? Deferred to design + accessibility review.
Follow-Up Engagement: Should user see follow-up reflection prompts after prayer, or is single prayer sufficient? UX refinement during beta.
Latency Tolerance: How long is user willing to wait for Rich Context synthesis + LLM generation before seeing first prompt? Target: <3 seconds. Exact timing TBD after Gemini integration.

Open Questions

  • Empty Context Fallback: User's first soak has 0 past moments. Should Gemini generate generic fallback prompts/prayer, or should soaking be disabled until user has multiple moments?
  • Moment Recency Bias: Should Rich Context weight recent moments more heavily than older ones, or equal weight across window?
  • Reflection-Moment Linking: Can user view past reflections linked to a moment? Or are reflections standalone?
  • Biometric Unlock for Soaking: Should soaking require Face ID / Touch ID unlock for additional intentionality? Or authenticate via regular app launch?
  • Theme Personalization: Should prayer tone/length adapt to user intents (e.g., "Process emotions" → longer, more exploratory prayer)?
  • Engagement Gating: Should we gate full soaking behind minimum engagement (e.g., user must read prompts before prayer appears)? Or allow skip-to-prayer?
  • Gemini Safety Guardrails: How do we prevent Gemini from generating spiritually inappropriate or harmful prayer content? Prompt engineering vs. moderation layer?

Success Metrics (Phase 2 Beta)

  • Soak Adoption: >70% of users soak at least once per week (triggered from post-capture)
  • Prompt Engagement: >80% of users read all 3 reflection prompts (not skipping)
  • Prayer Completion: >85% of users who see prayer read it fully (not abandoning mid-prayer)
  • Reflection Save Rate: >40% of post-soak sessions result in saved reflection
  • Time-in-Soak: Average 3-5 minutes per soaking session (indicates contemplation, not rushing)
  • LLM Quality: >75% user satisfaction with relevance of prompts + prayer (rated in post-soak survey)
  • Latency Performance: <3 seconds from "Pray on This Moment" tap to first prompt display

Integration Points with Other Pillars

Pillar Integration
Pillar 0 (Onboarding) User intents selected during signup feed into prompt + prayer personalization. Gemini uses intents to tailor reflective guidance.
Pillar 1 (Capture) Post-capture completion screen CTAs route to pillar 3. "Pray on This Moment" is primary CTA, indexing users toward soaking.
Pillar 2 (Security) Rich Context decrypts moments locally in RAM. Plaintext passed to Gemini API (trusted third party). Reflections encrypted before sync to Supabase.
Pillar 4 (Editing) Users can edit original moment post-soak. Can also edit saved reflections. Changes re-encrypted and synced.
Pillar 5 (Search) Reflections searchable alongside moments. Users can filter by "has reflection" to find contemplative moments.
Pillar 6 (Menu Bar) Soak tab (future) shows recent soaking sessions + reflections. Today tab shows moments + reflection status.
Pillar 7 (Notifications) Notifications can prompt: "Soak on [Moment Title]?" Soak engagement informs notification frequency/personalization.

Blocking & Dependencies

Pillar 3 depends on: Pillar 0 (intents), Pillar 1 (captured moments), Pillar 2 (encryption for decryption).

Pillar 3 blocks: Pillar 4 (editing) can proceed in parallel, but full narrative continuity requires Pillar 3's reflection context.
